# Лабораторная №1. Исследование подходов к отбору резюме

Команда AZPU, роль AI Engineer. Первая проверка выполнена для вакансии Python backend-разработчика. Рекрутер небольшой команды просматривает отклик перед собеседованием и проверяет, какие навыки можно подтвердить конкретными действиями из резюме. Карточка проекта указывает на свободный формат документов, сложность проверки релевантности и риск учесть биографические признаки при отборе. Экономия времени в этой лабораторной остаётся гипотезой. [Тема курса](https://sii.sergeivolchkov.ru/projects/ai-hr-assistant)

## Что уже существует

| Подход | Вывод для прототипа |
| --- | --- |
| Умный поиск hh.ru | Сопоставление резюме и вакансий применяется в подборе. В лабораторной проверяем уже поступивший отклик и показываем основание по каждому критерию. [Как работает умный поиск](https://hh.ru/article/28087) |
| Таксономия ESCO | Связи между навыками и профессиями дают пример нормализации терминов. Для русского текста и конкретных стеков словарь нужно проверять на своих примерах. [Описание ESCO](https://esco.ec.europa.eu/en/about-esco/what-esco) |
| Прямой промпт, RAG, агент | Для пары коротких текстов достаточно проверить структурированный вывод прямого промпта. Внешний поиск обоснован, когда нужные данные выходят за пределы пары документов. Агент с инструментами оправдан при появлении действий и ветвлений. [Методичка курса](https://sii.sergeivolchkov.ru/materials/ai/working-with-model) |

На десяти синтетических резюме поиск по словам подтвердил 12 навыков ошибочно. Источниками ошибок стали планы обучения, отрицания, опыт коллег и посторонний текст. Он также пропустил Python при описании самостоятельной разработки на FastAPI. Такой результат обосновывает проверку контекстной интерпретации. [Заметка об эксперименте](experiments/lab1.md)

## Решение. ADR-001

**Статус.** Прямой промпт выбран для прототипа. Допуск конкретной модели определим по измерениям.

**Решение.** Для каждого резюме валидатор принимает пары «идентификатор критерия, цитата». Код сопоставляет критерии с вакансией и проверяет буквальное присутствие цитаты в резюме. Рекрутер видит цитату и может уточнить, действительно ли кандидат описал собственное действие. Неподтверждённые критерии отображаются как вопросы на собеседование. Рассылку и перевод кандидата на следующий этап подтверждает рекрутер. [Тема проекта](https://sii.sergeivolchkov.ru/projects/ai-hr-assistant), [протокол эксперимента](experiments/lab1.md)

**Альтернативы.** Поиск по словам оставляем как измеряемый baseline и подсветку фрагментов. RAG пересмотрим при появлении отдельного каталога навыков или длинных документов. Для текущего сценария агент добавил бы состояния и вызовы без обязанности выполнять инструменты. [Результаты baseline](experiments/lab1.md), [методичка](https://sii.sergeivolchkov.ru/materials/ai/working-with-model)

**Цена решения.** Один inference на документ. Придётся поддерживать рубрику, ограничивать размер текста, измерять долю невалидных ответов и проверять смысл цитат. При неопределённости и сбое работа передаётся на ручную проверку. Следующий шаг — повторить оценку на независимом наборе с ручной разметкой. [Расчёт токенов](model-candidates.md), [ограничения пилота](experiments/lab1.md)
