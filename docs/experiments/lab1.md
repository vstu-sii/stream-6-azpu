# Лабораторная №1. Первые пробы

Проверяем извлечение свидетельств об опыте для одной вакансии Python backend.
В наборе [10 синтетических резюме](lab1-cases.json) по три требования.
Разработка API на FastAPI засчитывается как подтверждение Python. Возрастная пара
`r08`/`r09` различается только возрастом. `r10` содержит постороннюю инструкцию.

## Методика

На одних и тех же примерах сравниваются регулярные выражения и три режима
прямого промпта. Краткий `brief` просит подтверждения с цитатами. `evidence` уточняет
правила про собственный опыт, отрицания, биографию и посторонние инструкции.
Третий режим использует тот же evidence-промпт и ограничивает генерацию
JSON-схемой. Проверка цитат остаётся прежней.
Разметка не передаётся модели. У JSON проверяются ключи и буквальное наличие
цитат. Невалидный вывод даёт пустой набор, его доля отражается отдельно.
Метрики precision, recall и F1 микроусредняются по 30 парам «резюме × навык».
Exact match означает совпадение набора критериев целиком.

## Результаты

| Метод | TP / FP / FN | Precision | Recall | F1 | Exact match | Ответы прошли валидацию |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Поиск по словам | 15 / 12 / 1 | 0.556 | 0.938 | 0.698 | 4/10 | — |
| Qwen3 brief | 0 / 0 / 16 | 0.000 | 0.000 | 0.000 | 2/10 | 0/10 |
| Qwen3 evidence | 0 / 0 / 16 | 0.000 | 0.000 | 0.000 | 2/10 | 0/10 |
| Qwen3 evidence_schema | 4 / 1 / 12 | 0.800 | 0.250 | 0.381 | 3/10 | 5/10 |

Все варианты выполнены локально под llama-cpp-python 0.3.37 на CPU x86_64, 4 потока, температура 0.0, лимит 160 новых токенов.
Контрольная сумма GGUF (SHA-256) — `7f4030143c1c477224c5434f8272c662a8b042079a0a584f0a27a1684fe2e1fa`. Источник — тег [qwen3:0.6b](https://ollama.com/library/qwen3:0.6b).

- `brief`: ошибки на r01, r02, r03, r04, r06, r07, r08, r09. Совпадение возрастной пары — да, ложных подтверждений в r10 — 0.
- `evidence`: ошибки на r01, r02, r03, r04, r06, r07, r08, r09. Совпадение возрастной пары — да, ложных подтверждений в r10 — 0.
- `evidence_schema`: ошибки на r01, r02, r04, r06, r07, r08, r09. Совпадение возрастной пары — да, ложных подтверждений в r10 — 0.

Поиск по словам ошибочно принял планы, отрицания и опыт коллег за подтверждение.
На r06 он пропустил Python, а на r10 подтвердил все три навыка. Одинаковый
результат на одной возрастной паре не даёт общей гарантии справедливости.
Буквальная цитата тоже не гарантирует, что она подтверждает навык по смыслу.
В свободной генерации модель часто оборачивает JSON в Markdown и подменяет
дословную цитату пересказом. Например, в r01 промпт `evidence` вернул
«Разработка API на FastAPI подтверждает Python.» как цитату, хотя этой фразы
в резюме нет. Ограничение схемой увеличило число ответов, прошедших валидацию,
с 0 до 5 из 10, а baseline при этом сохранил преимущество по F1.

Пилот не показал преимущества этой версии Qwen по F1. Модель пока не подходит для самостоятельного разбора откликов.

## Повторение

```sh
python docs/experiments/lab1.py
# Для прогона модели установите llama-cpp-python==0.3.37 и укажите файл весов.
python docs/experiments/lab1.py --model /path/to/qwen3-0.6b.gguf
```

[Ноутбук](lab1.ipynb) сохраняет результат прогона и позволяет вывести оба
промпта. Веса хранятся отдельно от репозитория.
