# Лаба 3. Локальный baseline по резюме

## Что проверили

Реализовали `POST /v1/ai/assessments` по [контракту лабы 2](../../api/openapi.yaml).
Одни и те же 10 синтетических резюме прогнали через HTTP-слой ASGI с двумя
локальными GGUF. Использовали CPU x86_64, 4 потока, llama-cpp-python 0.3.37,
температуру 0, контекст 2 304, максимум 256 выходных токенов. Каждый запрос
имеет trace ID. Задержка замерена на этапе модели вместе с токенизацией,
разбором ответа и первым холодным стартом, без загрузки файла по HTTP.
p95 на 10 запросах — максимальное наблюдение по ближайшему рангу.

Первая версия формата допускала пустой массив. Qwen3-4B использовала его на
всех 10 примерах и получила F1 0. Поэтому во второй версии потребовали
явный ответ по каждому критерию: цитата из сегмента или null. Ниже результат
обеих моделей на одинаковом промпте второй версии.

## Метрики

| Модель | TP / FP / FN | F1 | Полное совпадение | p50 / p95, с | Токены вход / выход, среднее | Ошибки модели |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| [Qwen3-0.6B](lab3-qwen06b.csv) | 1 / 0 / 15 | 0.118 | 3/10 | 3.48 / 4.34 | 310.5 / 78.7 | 0 |
| [Qwen3-4B](lab3-qwen4b.csv) | 10 / 3 / 6 | 0.690 | 2/10 | 7.73 / 16.43 | 310.5 / 70.0 | 0 |

4B улучшила F1 на том же тесте. Для следующей итерации берём 4B как локальный baseline, а 0.6B оставляем контрольным вариантом. Поиск по словам в лабе 1 дал F1 0,698, но подтвердил 12 навыков
ошибочно. У 4B на этих примерах ложных подтверждений — 3, пропусков —
6. Пилот не измеряет качество на резюме реальных кандидатов и
переиспользует набор предыдущего спринта. В лабе 4 нужна отдельная разметка.

Изначальный проектный предел около 5 с обсуждался для облачной модели. Для
CPU-версии оценивайте задержку по таблице и показывайте ожидание в интерфейсе.
CPU-прототип использует ограниченный контекст и 256 выходных токенов.
Постоянный стоп при достижении времени в этом baseline не реализован.
При недоступных весах, превышении контекста или поломанной структуре API
отдаёт ручную проверку. Повторы одинаковой генерации при температуре 0
отключены: они увеличат задержку без гарантии нового результата.

## Как повторить

Установите зависимости из `requirements.txt`. Получите GGUF c такими
контрольными суммами SHA-256:

- [Ollama qwen3:0.6b](https://ollama.com/library/qwen3:0.6b) —
  `7f4030143c1c477224c5434f8272c662a8b042079a0a584f0a27a1684fe2e1fa`
- [Ollama qwen3:4b](https://ollama.com/library/qwen3:4b) —
  `3e4cb14174460404e7a233e531675303b2fbf7749c02f91864fe311ab6344e4f`

```sh
python docs/experiments/lab3.py --model /path/qwen3-4b.gguf --output /tmp/azpu-4b.csv
python -m uvicorn backend.app:app
```

Скрипт проходит весь путь через эндпоинт. CSV хранят фактическую задержку,
токены, исход и идентификатор каждого вызова. [Ноутбук](lab3.ipynb) пересчитывает
качество по сохранённым CSV. Для запуска самого API задайте `AZPU_MODEL_PATH`.
[Как открыть трассировку](../../ml/tracing/README.md).
